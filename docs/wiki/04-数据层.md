# 04 · 数据层

`client/src/data/`。五个文件，职责严格分开。

| 文件 | 职责 | 接真模型后 |
|---|---|---|
| `writingBands.js` | 学段定义、挑词开关、**提问红线** | **保留**，判据要写进 system prompt |
| `lexicon.js` | 好词词库 + 规则挑词 | 保留，变成给模型的候选提示 + 离线兜底 |
| `mockFilm.js` | 临时应答器：模拟"有人读了这句并回应" | **删掉**，换成 fetch |
| `prompts.json` | 作文题库（知识库） | 保留，内容由教师提供 |
| `promptStore.js` | 题库检索 | 保留 |

## 一、`writingBands.js` — 学段与提问红线

```js
PICK_WORDS_FROM_GRADE = 3        // 课标把"有新鲜感的词句"放在第二学段(3-4)
BANDS = [lower(1-3), upper(4-6)]
shouldPickWords(grade)           // grade >= 3
isReaderQuestion(question, sentence)   // 提问红线
```

**为什么开关按年级而不按学段带**：学段带是 1-3 / 4-6，而课标的分水岭在三年级。
三年级落在低段里，所以只选段定不了行为，必须选到年级。
这也是入口要选到年级而不是只选学段的原因。

### `isReaderQuestion` — 产品唯一的提问红线

来源是管建刚的"号脉"论证：没看到学生写出的东西就指导，一切指导都是假想。

```js
// 合格
A. 引用了孩子句子里的实词      "你写到'粗糙'——摸起来什么感觉？"
B. 读者陈述自己的阅读状态      "读到这里我想知道后来呢"

// 不合格
C. 替孩子决定写什么            "下一句写阳光落在哪儿"
C. 句型填空                    "它______得像______"
```

规则版只能做模式匹配，很粗。**真模型接上之后这条判据必须写进 system prompt
让模型自己保证**，这里的匹配降级为兜底。

## 二、`lexicon.js` — 好词词库

七类，约 200 词：四字词语/成语、色彩词、叠词形容词、气味词、声音词、
动作词、光线与时间。

```js
pickWords(sentence)   // 长词优先、不重复、不重叠、最多三个，按出现顺序返回
```

**为什么按长度倒序查**：否则「金光闪闪」会被「金光」抢先匹配，
「香气扑鼻」会被「香气」截断——长的那个才是更好的词。

**它和"让模型随便挑"的区别**：这些词是教学中真实存在的"好词好句"范畴。
孩子作文里出现这些词，语文老师本来就会画出来。所以这不是糊弄，
是一个有教学依据的近似。

**它的边界（重要）**：孩子写「今天我很开心」，这里挑不出东西。
那种情况该由大模型来问「怎么个开心法」——**规则引擎不装懂**。

**低年级不启用**（见 02 · 教学设计依据第五节）。

## 三、`mockFilm.js` — 临时应答器

**这个文件接真模型后整个删掉。** 它的形状就是契约的形状。

### 数据模型

```js
Frame = {
  id, text,              // text 是孩子写的中文原句
  picks,                 // 有新鲜感的词；低年级恒为空
  revision,              // 第几版，0 = 原稿
  previous,              // 上一版原文，用于并排对比
}

Question = {
  id, text,
  kind: 'cheer' | 'reader' | 'revise'
}
```

`revision` 和 `previous` 是为了落实课标的"修改自己的习作"——
**改前改后都留着，"我改了什么"要看得见**。

### 三种问题语气

| kind | 用在哪 | 例子 |
|---|---|---|
| `cheer` | 一二年级专用 | "这句我记下了，写得很有意思。" |
| `reader` | 产品主要形态 | "你写到'粗糙'——那个时候你自己身上是什么感觉？" |
| `revise` | 偶尔，不一直往前赶 | "这句读起来有点赶。哪一句可以拆成两句？" |

`cheer` 存在的理由：课标第一学段只要"乐于运用"，不施加质量标准。
`revise` 偶尔出现，是为了不让产品变成"只会往前赶"。

**兜底**：万一模板撞上预判形态，退到读者自述，**不放行一句"下一句写XX"**。

```js
if (!isReaderQuestion(question.text, text)) {
  question = { id: `q${turn}`, text: READER_VOICE[0], kind: 'reader' };
}
```

### 导出

- `STAGES` — 两个学段带
- `seedFilm` — 示例作文《爷爷的工坊》3 格
- `getSeedFilm(grade)` — 按年级取初始状态。低年级的第一句**不能是读者提问**，
  一上来就问"粗糙摸起来什么感觉"是施加质量标准
- `mockRespond(sentence, grade, turn)` — 模拟一次提交
- `makeRevision(frame, newText)` — 改版，旧原文退到 `previous`

## 四、`prompts.json` — 作文题库（知识库）

**当前 `prompts: []`，内容是空的。** 工具就绪，等教师提供。

### 为什么题库放前端而不是后端接口

题库是几百条结构化事实，总量几十 KB，打进包里比每次请求后端更快也更稳；
演示版是纯静态构建（`vite preview`），不依赖服务器就能跑。
出处靠每条记录自带的 `source` / `sourceDetail` 保证，不靠接口。

题库长到几千条再改后端检索——**存储位置换掉即可，字段和 `promptStore.js`
不用动。**

### 一条记录

```json
{
  "id": "p-4-upper-0768436",
  "grade": 4,
  "band": "upper",
  "title": "推荐一个好地方",
  "form": "xizuo",                    // dahua 写话 / xizuo 习作
  "type": "scene",                    // person/scene/object/event/imagine/practical
  "source": "textbook",               // textbook 教材 / exam 考题 / ningxia 家乡题材
  "sourceDetail": "部编版四年级上册 第一单元习作",
  "status": "verified",               // verified 可显示 / draft 待审核不显示
  "hints": ["这个地方在哪儿", "…"],
  "keywords": ["五颜六色", "生机勃勃"],
  "payoff": "picturebook"
}
```

### 三类来源的可信度不同

| source | 可信度 | 谁能填 |
|---|---|---|
| `textbook` | 最高 | 教师/教研组 |
| `exam` | 中 | 教师/教研组 |
| `ningxia` | 低（本组自编） | 本项目组 |

`ningxia` 一律先 `draft`，确认后才能转 `verified`。**它是家乡题材，
不是任何考试的题，不得冒充教材。**

## 五、`promptStore.js` — 检索层

```js
getBands()                    // 学段带列表
getPromptsByBand(bandId)      // 一个带下所有**可显示**的题目
getPromptsByGrade(grade)
getPromptById(id)
describeSource(prompt)        // 出处的可读文案，产品里要对家长出示
getBankStats()
```

**三条规则**：
1. **只暴露 `status: 'verified'`。** 宁可题库空着让调用方走降级，
   也不把没核对过的题目当教材推给孩子
2. **返回副本**，调用方改返回值不能污染题库
3. **题库为空不是错误**，调用方必须处理空数组

## 六、导入工具：`scripts/import-prompts.js`

零依赖（本机没 Python，也不想为构建期脚本装包）。
换台机器照样能跑。

```bash
node scripts/import-prompts.js --template                    # 生成带表头的空模板
node scripts/import-prompts.js <csv路径>                      # 合并（按 年级+题目 更新/新增）
node scripts/import-prompts.js <csv路径> --replace           # 全量替换
```

### 四道校验（都实测过会拦截）

| 校验 | 拦截什么 |
|---|---|
| **UTF-8 检测** | GBK 字节按 UTF-8 解会出 U+FFFD。中文 Windows 上 Excel 默认存 GBK，不拦住就会静默生成一份乱码题库 |
| **必填列 + 枚举值** | `form` 只能是 dahua/xizuo，`grade` 必须 1-6… |
| **个人信息红线** | `sourceDetail` 里出现"小学/中学/学校/老师/教师/导师/同学"直接拒。
  只能写到教材单元、地区、年份 |
| **退出码** | 有错误就不写文件，不会生成半份题库 |

字段说明见 [`docs/作文题库-字段说明.md`](../作文题库-字段说明.md)，
那是给填表的人看的，不是给开发者看的。

## 七、题库内容的三个来源（谁负责什么）

| 层 | 条数/年 | 谁填 | 状态 |
|---|---|---|---|
| 教材习作 | ~16 | 教师/教研组 | ⬜ 等提供 |
| 地区考题 | ~15 | 教师（教研组手里有） | ⬜ 等提供 |
| 家乡题材（宁夏） | ~10 | 本项目组 | ⬜ 未开始 |

**为什么必须混三类**：部编版每册只有 8 个习作，一学年 16 个，
**撑不到每年级 30-40**。要凑够必须混入试卷题/教辅题，而那些来源质量参差。

**大模型只做冷启动且必须过审**：先起草一版标 `status: draft`，
教师审核后才进正式库。它省的是时间，不替你决定内容。
（理由见 02 · 教学设计依据开头：事实性内容不允许编造后直接呈现。）
