# 01 · 产品与方向

> **2026-10-31 重写。** 本篇原先是 v1「作文学伴」的描述（胶卷 / 绘本放映 /
> 一句一句写 / 语音输入），那套产品已整体下架，历史见 git 与 `06` 文末"已作废"。
> 现在写的是当前产品「**范文放大镜**」。改产品前先读本篇，别从别处推断。

## 一、产品是什么

**范文放大镜**——面向**小学 3-6 年级**的语文作文工具。
AI 拆解一篇优秀范文，把"这一句好在哪里"变成孩子能拿走就用的一招；
孩子用这一招写一句自己的，然后有一个"读者"回应他。

节拍像游戏开局，不像表单：

```
开始 → 选年级 → 选范文 → 拆解 → 用一招写自己的
```

| 拍 | 屏幕 | 为什么单独占一拍 |
|---|---|---|
| 开始 | `StartScreen` | 第一眼看到表格或说明，孩子就认定"这是作业"；看到一个大按钮才会想按 |
| 选年级 | `StageGate` | 拆解深度按年级分叉，这一步是产品在做判断，不是收集信息 |
| 选范文 | `EssayPicker` | 内置 79 篇，或贴一篇自己的 |
| 拆解 | `MoveCards` + `ChallengeCard` | 出招式卡；支架撤除生效时还要孩子自己找一句 |
| 用一招 | `TaskDock` | 产品的闭环——拆解不是终点，"用这一招写一句自己的"才是 |

三个阶段在**一页里**推进，不跳路由：从"看懂"到"动手写"之间每多一次页面切换，
就多一个放弃点。点「用这一招」只是把右栏滚到写作坞，范文还在原处没动。

深链：`?grade=3..6` 跳过前两拍，`?essay=<id>` 直接开到拆解——录演示视频用。

## 二、脊柱：例文说 + 支架式教学

**这是产品最重要的一个决定，2026-10-29 定，依据见 `02`。**

| 理论 | 在产品里的位置 |
|---|---|
| **王荣生"例文"说** | 主脊柱。范文是"教写作的样例"，拆解它是为了让学生获得**可迁移的写作知识**——不是让学生模仿这一篇，是让学生拿走其中的一招 |
| **布鲁纳 支架式教学** | 主脊柱。产品的支架就是"直接标好的那几招"，它必须**逐步变薄**，否则就是新型句型填空 |
| **荣维东 交际语境写作** | **降级**为阶段三"读者身份"的约束。它回答不了"它怎么教会写作" |
| **管建刚 作后讲评** | **只是约束，不是依据**。他的"反对作前指导"翻译成产品语言是"不许预判"——不能替孩子决定下一句写什么。别再试图把他缝回依据位 |

**新红线只有一条：教方法，不给内容。**
AI 给招式、给"这一句里发生了什么"、给"你可以怎么用"，但不给句子、
不出"写一句______"这种填空模板。用户一眼就能看出"这只是填空游戏，不是智能体"。

## 三、三个阶段各自在做什么

### 阶段一 · 选范文

两条路都重要：

- **内置 79 篇**（`grade-{3..6}.json`，按年级分片动态加载）——
  让人点开就看到东西，且命中预处理、**不调模型、0.04 秒返回**。
  全部自撰，界面上标"示例范文"，不抄教材课文
- **贴一篇自己的**——真实使用路径（评委现场贴一篇也能拆），
  且零版权风险：原文只在请求里流转，不落库。走实时链路，
  **25-60 秒、依赖 Key 有效**，这是产品当前最大的风险

### 阶段二 · 拆解

产物四样，缺一样产品就不成立：

| 产物 | 是什么 |
|---|---|
| **招式卡** | 每张四样：招式名、范文原句、这一句里发生了什么、孩子可以怎么用。最后一样是**方法级**的 |
| **challenge** | 支架撤除的补偿：从原文另找一处用了招的句子，只给原句不告诉他是哪一招 |
| **basis** | 智能体现身的地方——它照什么拆的（知识库哪几张卡）、核对结果如何 |
| **precomputed 标记** | 命中预处理时前端必须显示"提前算好的"，不冒充当场拆的 |

**引用必须逐字出自原文，服务端机械校验。** 模型偶尔会把段落改写一遍，
孩子看到的就会是一篇被改写过、却冒充原文的作文。
`isValidAnalysis` 返回**具体拒绝原因**而不是布尔，自纠错要靠原因。

**支架撤除是合取**（`server/src/agent/fading.js`，一处收口，prompt /
预处理仓 / 实时链路三处共用）：学过几招 **且** 在几篇里用出来过。
两个数各自防一种失败——只数学过的招，学了很多从不动笔的孩子会被过早撤除；
只数用出来过，只学一招反复写的孩子撤了也没东西可找。
依据见 `07`（Renkl & Atkinson 2003）。

### 阶段三 · 用一招写自己的

`TaskDock`。孩子点「用这一招」→ 写一句自己的 → 给"读者"看。

- **读者的身份是读者不是老师**：它回应孩子刚写出的句子，不替他决定下一句写什么。
  这条边界由服务端 `isReaderQuestion` 兜底（规则版只能模式匹配，真保证在 system prompt 里）
- **读者回信用「信纸」承载**：信头 + 信身 + 落款"—— 你的读者"。
  落款不写具象角色，人格从文字来
- **写完那句飞一张黄便签进册子**（收招式是飞白牌，两样东西飞两个样子）

## 四、两条工作线：引导与激励

> 2026-10-31 用户定的深入方向。**它取代了 v1 的"两根支柱"**——
> 旧说法是两**个页面**（引导写 / 作文变作品）加一个"绘本越丰富作文越具体"的咬合点，
> 第二页已不存在。引导与激励不再是两个页面，是同一套闭环里的两条工作线，
> 实证依据全部落在 `07`。

| 线 | 做什么 | 防什么失败 |
|---|---|---|
| **引导** | 招式卡（给支架）→ `challenge`（说清楚：你自己看这是哪一招）→ 合取撤除（变薄） | 支架永远不撤 = 新型句型填空；撤得太快 = 孩子没东西可找 |
| **激励** | 册子（三种来源）→ 头衔 → 读者来信 | 追加奖励会让孩子追奖励而不是追写法 |

**激励是证据不是奖励，不加积分星级连击排行榜。**（决策 42）
真正在做的是把已有的补完整：自己的句子要能读回来、两个数要分开算。

册子（`client/src/lib/moveBook.js`）的三种来源：

| 来源 | 是什么 |
|---|---|
| `essay` | 从范文学来的招 |
| `own` | 自己用上的那句 |
| `spotted` | **自己看出来的招**（challenge 的产物，articulation 的结果，孩子自己挣的那一类） |

三个计数各有驱动，**新增计数前先问"这个数驱动什么"**：
`countLearnedMoves` 和 `countOwnEssays` **合取**驱动支架撤除，
`favouriteMove` 驱动册子里"你最常用的一招"。

## 五、学段分叉（按年级，不是按学段带）

产品是 3-6 年级，但**行为开关按年级**——课标的分水岭在三年级，
而学段带是 3-4 / 5-6，选带定不了行为。

| 年级 | 课标落点 | 产品动作 |
|---|---|---|
| **3-4** | 不拘形式地写下见闻、感受和想象；尝试运用**有新鲜感的词句** | 招式少而具体 |
| **5-6** | 懂得写作是为了**自我表达和与人交流**；**修改自己的习作** | 要多说一层"和读者的关系" |

**1-2 年级不做**（决策 2）：识字量读不完一篇范文，
且课标第一学段要的是"乐于运用词语"——是树立运用意识，不是篇章质量。
别顺手把低段加回来。

## 六、已经裁掉、别加回来的

| 不做 | 为什么 |
|---|---|
| 假读者数（"3 位读者传阅"） | 没有人在读。它还把"有人在读"（定性，真）换成"有多少人读"（定量，假） |
| 让读者当审核（判"用到招式没有"） | 读者就变成老师。而且那个判定**服务端根本不做**——它只校验范文引用，不校验 `childText` |
| 实体 mascot / 盲盒多角色 | 与决策 22 冲突；随机人格会稀释单一人格的 token，正是"逐句镜像"那类失败的土壤 |
| 服务端判定用到招式就点亮图标 | 等于新建能力，且等于把审核从读者挪到服务端——产品性质从"有人读"变成"有人打分" |
| 按技巧种类算头衔 | 招式名没有分类法：257 个名字对应约 260 招，同一技术会有三个不同字符串，数它等于数字符串。按"用自己的话接过的篇数"算 |
| 语音输入 / OCR 拍照 | v1 的规划，本期未接。对外不要说"支持语音" |

## 七、技术栈与部署

**React + Vite（不用 TypeScript）+ Node/Express + StepFun（OpenAI 兼容）+ 魔搭创空间。**
不引新技术栈，比赛中途换框架是最高高频的死法。

| 项 | 值 |
|---|---|
| 模型 | `step-3.7-flash`（点不用横杠），`reasoning_effort=low` |
| 端点 | `https://api.stepfun.com/step_plan/v1`（**不是 `/v1`**，两个入口分开计费） |
| 超时 | 全局兜底 60000；`ANALYZER_TIMEOUT_MS` / `READER_TIMEOUT_MS` 都显式覆盖成 90000 |
| 部署 | 魔搭创空间，框架 docker / 免费 CPU / 端口 **7860** |
| 访问门槛 | 一个共享密码（`ACCESS_CODE`，只从环境变量来），不是管理员账号 |

**部署时必须显式填 `LLM_TIMEOUT_MS=60000`**，改完环境变量**必须重启创空间**。
不配 Key 内置范文照样能用——Key 只影响"粘贴一篇"那条路。

## 八、视觉

配色与字体是 oil-ui 三方向对比里由用户选定的，**作为锁定品牌资产沿用**，
调性五刻度已由用户实测证据锁定，不重开。改任何颜色前先确认它对应哪条令牌，
不要新增魔法数字。

```
--sky    #bfe9ff   天蓝底。孩子的作业纸不该是白的
--ink    #17384d   墨蓝，压在天蓝上不脏
--orange #ff6b35   主强调      --yellow #ffd23f   荧光笔
--pink   #ff5d8f   次强调      --purple #a06cd5   第三种来源（challenge）
```

**字体是幼圆 + `-webkit-text-stroke: 0.7px`**，本机实测出来的甜点
（1.4px 笔画糊在一起，0.6px 偏软）。幼圆是唯一可用的圆体但只有 regular 一档；
微软雅黑 Bold 笔画太粗会把后面的黄色荧光笔压得看不见。
**换机器部署先确认目标机器有幼圆**，没有就退到微软雅黑并把描边降到 0.4px。

**动效常开，不跟随系统"减少动态效果"偏好。** 动效是这个产品的内容不是装饰——
落贴纸、发牌、那句飞进作文本全是反馈本身。各处的 `html.motion-off` 规则
保留着当无障碍退路，别删。

立体感统一来自"实心投影"（`--lift`），像一块厚纸板，不像漂浮的卡片。

### 用色规矩（2026-11-02 交互巡检后定，决策 74-77）

**橙和粉不做文字色，也不做小字的底。** 这两个色相里没有能过 4.5:1 的组合：
橙底白字 2.84:1、橙底 ink 字 4.34:1；粉底白字 2.91:1、粉底 ink 字 4.22:1。
能承字的浅底只有黄（ink 字 8.52:1）和天蓝（ink 字 9.54:1、ink-soft 字 4.94:1）。

| 位置 | 规矩 |
|---|---|
| **主动作**（用这一招 / 给读者看看 / 拆开这篇 / 进去） | ink 底白字 12.29:1。三屏主动作长得一样，孩子不用重新学 |
| 开始按钮 | **唯一例外**：保留橙底，字改 ink（4.34:1，而它是 24-32px 粗体，按 WCAG 算大字、过 3:1 那条线）。开始屏是产品的脸，橙色是它唯一的强调色 |
| 小签 / 元信息（你可以怎么用、卡片 meta、basis 标题） | ink-soft，6.35:1，仍比正文低一档 |
| kicker  pill（该你写了 / 你自己看） | ink 底白字 |
| 错误条 | 白底 ink 字 + 粉边——"出错了"交给粉色边线说，字本身要看得清 |
| 橙色还在哪儿 | 牌子左边那道厚边、范文里涂黄的荧光笔、focus 轮廓。**不当文字色** |

年级卡上原本每个数字底下有个 12px 的「年级」小签，**删了**（决策 77）：
它在粉卡上只有 4.22:1，而这套色板里没有强调色能在 12px 上过线；何况它和
band 标签「三四年级 / 五六年级」、以及问题本身「你现在几年级？」是三层重复。
