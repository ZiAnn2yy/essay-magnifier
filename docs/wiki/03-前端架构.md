# 03 · 前端架构

`client/`，React 18 + Vite 6，**不用 TypeScript**，ESM。
CSS 用普通样式表（不用 CSS-in-JS、不引 Tailwind）——动效需要关键帧，
样式表是最直接的工具。

---

## 目录

```
client/
├── index.html                      # 标题、viewport、theme-color
├── vite.config.js                  # /api 代理到后端（PORT 由 VITE_API_TARGET 定）
├── public/fonts/
│   └── fredoka-latin.woff2         # 29KB 可变字体，自托管（不走 Google Fonts）
└── src/
    ├── main.jsx                    # createRoot + StrictMode
    ├── App.jsx                     # 选年级 → 工作台 的切换 + ?grade= 深链
    ├── api/client.js               # ⚠️ 骨架期的 HTTP 客户端，现已被 mock 取代（死代码）
    ├── styles/app.css              # 设计令牌、字体、关键帧、@media reduced-motion
    ├── data/                       # 见 04 · 数据层
    └── components/
        ├── StageGate.jsx/.css      # 入口：选年级（1-6，分两个学段带）
        ├── Workbench.jsx/.css      # 第一页主体：一屏四区的容器与全部交互状态
        ├── Screen.jsx/.css         # 大银幕：当前句放大、荧光笔、改版留痕
        ├── Reel.jsx/.css           # 胶卷：一句一格、空格虚线、新格落入动画
        ├── AskDock.jsx/.css        # 底部：读者回应 + 输入 + 「放给他们看！」
        ├── ThinkLoader.jsx/.css    # 透明加载框：四步动画，覆盖整块问答区
        └── Screening.jsx/.css      # 放映模式：全屏、深底、逐格自动播放
```

每个组件配一个同名 `.css`，由组件自己 import。样式不集中到一个大文件——
改一个组件不该打开全部样式。

## 数据流

```
App (grade)
 └─ Workbench                      ← 全部交互状态都在这里
     ├─ Screen      frame, index, total, picksEnabled
     ├─ Reel        frames, activeId, lastAddedId, onSelect
     ├─ AskDock     question, draft, onSubmit, submitLabel, isThinking, onPlay
     ├─ ThinkLoader sentence, picks, onDone        ← 条件渲染（isThinking）
     └─ Screening   frames, title, picksEnabled     ← 条件渲染（isScreening）
```

**状态全部在 Workbench，子组件无状态**（除 FilmTitle 这个局部编辑态）。
这不是洁癖——胶卷的交互是一环扣一环的（提交 → 加载 → 新格落入 → 银幕滑入
→ 新问题），状态散开就会出现竞态。

## 三处基本动效

不用 linear/ease 的"默认感"，全部 `cubic-bezier` 过冲——
孩子的产品里东西要"啪"地到位，不要"渐"地出现。

| 动效 | 关键帧 | 触发 |
|---|---|---|
| 新句从右滑入银幕 | `slidein` | 换格（`key={frame.id}` 让节点重建，动画才会重放） |
| 新格"啪"地落入胶卷 | `dropin`（缩小+倾斜+过冲回正） | `lastAddedId` 命中的那一格 |
| 关键词荧光笔从左划过去 | `swipe`（`scaleX(0→1)`） | 银幕滑入后延迟 0.24s |
| 挑中的词浮出来 | `pickin` | 银幕底部信息带 / 放映模式片尾字幕 |

`@media (prefers-reduced-motion: reduce)` 里全局压平动画。

## 两个踩过的坑（别再犯）

### 1. 挑词必须在**渲染时**按年级决定，不能存进数据

第一版把 `picks` 写死在种子里，学段开关只作用在新句子上，
结果**二年级一进来看见种子的"唯一/粗糙"被高亮了**。

修法：`Screen` 和 `Screening` 都接收 `picksEnabled`，
`const picks = picksEnabled && frame.picks ? frame.picks : []`。
存进去的话，中途改年级还会出现"这一格亮、那一格不亮"的撕裂状态。

### 2. 本机无头截图在窄 viewport 下会骗人

`msedge --headless --screenshot --window-size=390,844` 实际渲染宽度比请求的宽
（本机 DPI 144 / 缩放 1.5 干扰），再把右侧裁掉，**看起来跟布局横向溢出
一模一样**。`--force-device-scale-factor=1` 也治不了。≥560px 正常。

**正确的验证方法**：写一个临时 HTML 用 `<iframe style="width:390px">` 加载页面，
读 `contentDocument.documentElement.scrollWidth` 和各容器的
`getBoundingClientRect().width` / `scrollWidth`。
`docScrollW === 视口宽` 就证明没有溢出。用完删掉临时文件。

## 字体：为什么是幼圆 + 0.7px 描边

本机实测四款中文字体 × 五种描边厚度（截图在 `.oil-ui/writing-agent-directions/shots/round2/14、15`）：

| 方案 | 问题 |
|---|---|
| 幼圆原生 | 唯一可用的圆体，但只有 regular 一档，700 是伪粗，撑不起"主角" |
| 微软雅黑 Bold | 有真粗，但笔画太粗，**把后面的黄色荧光笔压得看不见** |
| 华文楷体 | 有语文/字帖的味道，但是书法体不是圆体，伪粗很难看 |
| 黑体 SimHei | 最重最硬，像政府标语 |
| 幼圆 + 1.4px 描边 | 笔画糊在一起 |
| **幼圆 + 0.7px 描边** | ✅ 既圆又有分量，荧光笔还在 |

```css
--font-round: 'YouYuan', '幼圆', 'Yuanti SC', 'STYuanti', 'Microsoft YaHei', sans-serif;

.screen-text {
  font-family: var(--font-round);
  -webkit-text-stroke: 0.7px currentColor;
}
```

**换机器部署先确认目标机器有幼圆**（Windows 有，macOS 对应 Yuanti SC）。
没有就会退到微软雅黑——那时要把描边降到 0.4px，不然太厚。

Fredoka（自托管 29KB）仍用于英文与数字（格号 `3/3`、入口页的 `MY LITTLE FILM`），
和幼圆同属圆体，混排不冲突。
