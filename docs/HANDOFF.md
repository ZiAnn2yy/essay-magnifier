## StepFun 端点（今天最大的一个坑，白跑了一轮）

**`https://api.stepfun.com/v1` 和 `https://api.stepfun.com/step_plan/v1`
是两个不同的计费入口。**

用户的 Credit 在 **Step Plan** 上，而 `.env` 里配的是普通端点——于是所有请求都打到
一个没有 Credit 的入口上，返回 `402 quota_exceeded`。
**同一把 key，只改 base URL，立刻全部可用。**

诊断方法（`server/scripts/diagnose-quota.mjs`）：逐个模型打极小请求。
**四个模型全部 402 → 账户/入口层面；只有一部分 402 → 按模型或产品分开计费。**
当时是前者，所以不是"新模型要付费套餐"。

> **教训：402 quota_exceeded 不一定是用光了。先确认端点对不对，再怀疑余额。**
> 我当时按"额度耗尽"处理，还算了一笔 108 次调用的账——那个账是白算的。

## 预处理（今天的核心交付）

```
server/scripts/precompute-analysis.mjs
  → 用同一个 buildAnalysis 逐篇算（含逐字校验与自纠错）
  → 落 server/data/precomputed/grade-N.json
  → 服务端取用时再拿请求里的原文复核一遍
  → 对不上就返回 null，退回实时链路
```

**实测效果**：内置范文 **0.04-0.05 秒**返回，完全不调模型。
`server/scripts/verify-all-essays.mjs` 是穷尽验证脚本，69 篇 × 2 种册子状态全过。

三条硬规矩：

1. **存的必须是过了同一道闸的结果**，不是另一套松逻辑
2. **essayId 是客户端给的，文本也是**，两者没有必然关系——取用时要复核
3. **返回带 `precomputed: true`，前端必须显示"提前算好的"**，不冒充当场拆的

两个变体：`base`（册子空）和 `scaffolded`（册子 ≥3 招，支架撤除生效，带 `challenge`）。
**scaffolded 缺失时退回 base，不退回实时链路**——它的约束更严、失败率更高，
为一句挑战句让孩子等 60-90 秒不值得。

脚本会自我修复：加载时按当前标准复核已有条目，不合格的当场丢掉、等重跑补上。
**提高校验标准后不需要手动清理旧数据，重跑一次自动修好。**

### 收工后又抓到一个：读者回应根本没有超时预算（第 5 个）

这份文档原先写着"`online-002` 在 temperature=1 下会偶发失败，重跑即可"。
**那是个误判。** 复跑时它连续三次红，而直接调 `buildReaderReply` 六次里
三次都返回完全正常的读者回应——差异不在提示词。

把原始返回打出来才看见：

```
[WARN] LLM 读者回应失败，使用兜底话术
       {"reason":"请求模型失败: The operation was aborted due to timeout"}
第2轮 60.0s degraded=true len=40
```

`len=40` 正是那句兜底话术的长度。**失败的是超时，不是风格。**

实测同一个读者任务 6 次：**4.2 / 9.3 / 30.6 / 31.4 / 40.8 / 60+ 秒**，
中位数就在 31 秒。而 `model/client.js` 的注释一直写着
"调用方可以按任务覆盖：拆解要 30-50 秒，**读者回应只要几秒**"——
后半句是猜的，代码里从来没有这个覆盖，读者一直吃全局 `LLM_TIMEOUT_MS`。

更要紧的是**三处口径不一致**：代码默认 `30000`、`.env.example` 写 `30000`、
本地 `.env` 是 `60000`。**部署到魔搭时若不显式填 `LLM_TIMEOUT_MS` 环境变量，
读者路径就按 30 秒砍——上述 6 次里有 3 次会失败**，孩子看到
"我现在没办法好好读你写的东西（模型没有连上）"。

修法四件事，理由见 `wiki/06` 第 36-39 条：

| 改动 | 文件 |
|---|---|
| 读者显式覆盖 `READER_TIMEOUT_MS=90000` | `src/agent/reader.js` |
| 全局兜底默认 30000 → 60000 | `src/config.js`、`.env.example` |
| 超时降级在评测里记 SKIP 不记 FAIL | `eval/run.js`、`eval/cases/online.js` |
| **新增 `budget-001` 锁死不变量** | `eval/cases/offline.js` |

最后一条是重点：真正该锁住的是"读者超时 ≥ 60 秒"和"调用点真的把预算传了下去"，
**不是让在线用例去赌模型心情**。阈值断言管不住"常量还在但调用处没引用它"——
这次的真因正是这个，所以 `budget-001` 同时读源码确认调用点。

顺带把读者失败的分类从"额度/其他"细化成 `timeout / quota / upstream /
unconfigured`（`reason` 字段），与 `analyze.js` 的 `classifyDegrade` 对齐。
评测的 SKIP 判据就建在这个字段上，**只认 timeout 一种**。

> **教训四：注释里承诺过的机制，代码里可能从来没有。**
> `client.js` 那句"调用方可以按任务覆盖……读者回应只要几秒"写了好久，
> 于是每个人都以为读者有自己的预算。它没有。
> **看见注释里写着某个机制，先去代码里确认它真的存在。**

### 第 4 个是最深的那个

prompt 一直要求"text 必须原样照抄该段原文"，但 `isValidAnalysis` 只查了非空。
于是模型偶尔把段落改写一遍（合并句子、动标点）也能通过——而 EssayPane 渲染的
正是这个字段，**孩子看到的就是一篇被改写过、却冒充原文的作文**。

它是这样被发现的：预处理仓里 13 个条目段落文本对不上，服务端读取时的复核闸

**存的时候不严，读的时候就只能慢。**

修法：`isValidAnalysis` 补上段落逐字校验。实时链路同样受益——模型会走自纠错，
那正是这道闸该有的效果。

## 五个必须知道的坑

**1. 本机沙箱会杀掉 `fs.cpSync(dir, dest, { recursive: true })`**

退出码 127、stdout/stderr 全空。同一个沙箱里 `cp -r` 和单文件 `copyFileSync` 都正常。
打包脚本已改成自己走目录树。

**2. 起服务前查端口；杀后台服务要用 netstat 找 PID**

旧进程还活着时新起的会 EADDRINUSE 退出，而请求全打到**旧代码**上。
另外：**每条 Bash 调用都是新 shell，上一条命令里的 `kill %1` 在新 shell 里不存在**，
后台服务要用 `netstat -ano | grep ':端口'` 找 PID 再 `taskkill //PID <pid> //F`。

**3. 动效常开，不跟随系统偏好**

用户明确要求。`html.motion-off` 那套 CSS 留着当无障碍退路，别删。

**4. 无头环境验不了动画时钟**

`currentTime` 停在 0。"动画到底动不动"只能由用户亲眼确认，**不要报告成已验证**。

**5. Key 别落到新文件**

既是安全风险也会被权限判定器拦下。备份 `.env` 变体前先 `git check-ignore -v`。

## 激励体系：方向已定，第一步已落地

用户提了一套"双向升级的作家与读者体系"（读者数量成长线 + 作家等级 + 读者来信）。
评审后**砍掉四样、留下一样**：

**砍掉**：
1. **假读者数**（"3 位读者传阅"/"100 个读者"）——没有人在读。它还把"有人在读"
   （定性，真）换成"有多少人读"（定量，假），而前者本来就是更强的驱动力
2. **让读者当审核**（"判断孩子有没有用到颜色连接"）——读者就变成老师，
   孩子第一眼知道这是作业。而且那个判定**服务端根本不做**，
   现有的逐字校验校的是范文引用，不是孩子写的话
3. **实体 mascot**（魔法猫、邮差小鸟）——与决策 22 直接冲突
4. **盲盒多角色**——单一人格是把 token 全砸在一次高质量共鸣上的前提，
   随机抽人格正是当初"逐句镜像"那类失败的土壤

**留下**：读者来信。而且查证发现**能力早就有了**——读者 prompt 里
"第一句话必须是你的感觉 / 挑一处说它为什么打到你 / 问一个能让他想接着写的问题"
三件套一行不缺，缺的只是呈现。所以做的是纯 UI：

- `TaskDock` 的「读者说」气泡 → `article.letter`：信头（来自读者的回信）+
  信身 + 落款（—— 一直在读你的人）。落款不写具象角色，人格从文字来
- 信纸：淡黄底 `#fffef0` + `repeating-linear-gradient` 画横线，
  正文 `line-height: 28px` 与横线间距对齐，每行落在格线上
- **不引新字体**（既有约定：不加依赖、包体积算过账），质感全靠布局和颜色
- 进场动画从"掉下来"改成"展开"（`scaleY(0.55) → 1`），像把对折的信打开
- 等待态分三档（8s / 25s），沿用 `Analyzing` 的路子。第二档
  「他读的是你写的句子，不是标准答案」是原有文案，是产品对"慢"的解释，保留
- 等待态末尾一个闪烁光标当笔尖。不画邮差不画鸟——"有人在写"一根笔尖就够

**顺带查清两件影响后续设计的事实**：
- **招式名没有分类法**。`move` 对象只有 `id/name/quote/why/tryThis`，257 个名字
  对应约 260 招，且存在同一技术三个字符串的情况。所以"点亮了几个技巧大类"
  这个轴在数据里不存在，数它等于数字符串
- 数据里稳定、有界、刷不动的轴只有：**拆过几篇（≤79）/ 在几种文体里写过（≤5）/ 写过几句**
